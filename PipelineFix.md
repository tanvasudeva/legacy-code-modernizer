## Bugs Fixed

### 1. `ServiceGeneratorAgentTest` — wrong constructor arity

### 2. Redis `BUSYGROUP` crash on restart (`StreamInitializer`)

Catch block checked `e.getMessage()` which returns `"Error in execution"` — not the BUSYGROUP string. Actual error text lives in `e.getCause().getMessage()`. Fixed to check both.

**File:** `orchestrator/src/main/java/com/legacy/modernizer/stream/StreamInitializer.java`

---

### 3. `NoUniqueBeanDefinitionException` — dual TransactionManagers

Spring Data Neo4j auto-registers `reactiveTransactionManager`. Combined with JPA's `transactionManager`, `@Transactional` methods fail with ambiguity. Created `TransactionManagerConfig.java` marking the JPA TM as `@Primary`.

**File:** `orchestrator/src/main/java/com/legacy/modernizer/config/TransactionManagerConfig.java` *(new)*

---

### 4. `LLM produced no <file> blocks` — `ServiceGeneratorAgent`

`qwen2.5-coder:1.5b` consistently omits the `</content>` closing tag before `</file>`. The FILE_BLOCK regex required it strictly. Made `</content>` optional:

```java
// Before
"<file>\\s*<path>(.*?)</path>\\s*<content>(.*?)</content>\\s*</file>"

// After
"<file>\\s*<path>(.*?)</path>\\s*<content>(.*?)(?:</content>\\s*)?</file>"
```

Also added markdown fenced-block fallback patterns and downgraded a debug log from INFO → DEBUG.

**File:** `agents/src/main/java/com/legacy/modernizer/agent/ServiceGeneratorAgent.java`

---

Identical regex fix applied.

### 7. `ZipException: duplicate entry: pet-service/pom.xml` — `BundleAssembler` *(Job 10→12)*

Once TestWriter and DocGen were fixed, they produced artifacts stored under the same service key (`classFqn`). The model occasionally emits a `pom.xml` inside test output, colliding with the service-code `pom.xml`. Fixed by changing the per-service grouping from `List<Artifact>` to `Map<String, Artifact>` keyed by `filePath`, with artifacts sorted by ID ascending so the latest version wins:

```java
byService.computeIfAbsent(svc, k -> new LinkedHashMap<>())
         .put(a.getFilePath(), a);  // last write (highest id) wins
```

**File:** `orchestrator/src/main/java/com/legacy/modernizer/bundle/BundleAssembler.java`

### 8. Repair loop silently gives up — `CompilationRepairService` *(Job 12→15)*

Root cause discovered by manually compiling the downloaded bundle. Each service `pom.xml` generated by `qwen2.5-coder:1.5b` has no `<parent>` block, so Maven fails on missing dependency versions before javac ever runs. The repair loop received empty javac output and logged "no parseable errors — giving up" after 0 repair iterations for every service.

Two fixes applied:

**`CompilationRepairService.compileArtifacts()`** — patch the pom.xml written to the temp compile dir before invoking Maven:
```java
String content = "pom.xml".equals(a.getFilePath())
        ? patchPomParent(a.getContent())
        : a.getContent();
```

**`patchPomParent()` utility** (added to both `CompilationRepairService` and `BundleAssembler`):
```java
static String patchPomParent(String pom) {
    if (pom == null || pom.contains("<parent>")) return pom;
    // fix common model mistake: wrong groupId for jakarta.persistence
    pom = pom.replace("<groupId>jakarta.persistence-api</groupId>",
                      "<groupId>jakarta.persistence</groupId>");
    // inject Spring Boot parent after </modelVersion>
    return pom.replace("</modelVersion>", "</modelVersion>\n" + SB_PARENT);
}
```

**`BundleAssembler`** — same patch applied at ZIP assembly time so the downloaded bundle also compiles cleanly.

**`CompilationRepairService.FILE_BLOCK`** — same `</content>` optional regex fix applied here too (was missed in the earlier pass).

**Files:**
- `agents/src/main/java/com/legacy/modernizer/agent/CompilationRepairService.java`
- `orchestrator/src/main/java/com/legacy/modernizer/bundle/BundleAssembler.java`
